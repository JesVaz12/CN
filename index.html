Bienvenida

Introducción

Este portafolio reúne las evidencias y desarrollos prácticos elaborados durante el curso de Cómputo en la Nube, la finalidad es documentar de forma estructurada el proceso de aprendizaje y las competencias adquiridas en el diseño y despliegue de soluciones tecnológicas, mostrando la evolución desde los conceptos teóricos iniciales hasta la implementación de infraestructuras complejas y seguras.

Propósito del Portafolio

Registrar de manera organizada y reflexiva las actividades de aprendizaje y este portafolio expone de forma directa la capacidad para planificar, desplegar y optimizar infraestructuras virtuales bajo un enfoque de mejora continua y eficiencia de recursos.

¿Qué se documenta?

El contenido abarca las prácticas y fundamentos teóricos clave del semestre, en este se incluyen análisis de topologías de red, el uso práctico de consolas en AWS, GCP y Azure, el despliegue de contenedores y diversas pruebas de robustecimiento y ciberseguridad en servidores web.

¿Por qué es importante?

La infraestructura en la nube representa el pilar del desarrollo de software moderno y el como comprender sus mecanismos es indispensable para construir plataformas que toleren altas demandas de tráfico, permanezcan seguras frente a posibles ataques y minimicen los costos operativos.

Enfoque y Metodología

Se utiliza una metodología basada en la experimentación directa y el aprendizaje activo e inicia con la asimilación de modelos de servicio y evoluciona hacia la resolución de casos reales, fomentando el análisis crítico y la autonomía técnica.

Unidad 01

Introducción y fundamentos de cómputo en la nube

El cómputo en la nube funciona bajo un modelo similar al de los servicios públicos tradicionales: los recursos informáticos se consumen bajo demanda y se facturan de acuerdo al uso real, en lugar de instalar y mantener servidores físicos locales en una oficina u hogar, este paradigma permite acceder a una red global de almacenamiento, procesamiento y redes administradas por terceros de forma remota.

¿Por qué aprender esto?

El estudio de estos conceptos es clave para entender la nube como una plataforma estratégica y no como un recurso aislado, es que el punto de partida indispensable para planificar arquitecturas que soporten el crecimiento de aplicaciones sin comprometer la estabilidad.

Esta tecnología ha democratizado el acceso a recursos informáticos avanzados, permitiendo que tanto proyectos personales y educativos como grandes infraestructuras corporativas compartan principios de alta disponibilidad, seguridad y distribución de carga.

Pilares del Servicio

La infraestructura destaca por su elasticidad, adaptando sus recursos en tiempo real según el volumen de usuarios, además, optimiza costos al sustituir gastos de capital en hardware por costos operativos, garantizando disponibilidad continua y un aislamiento riguroso de la información.

Capas de Entrega (XaaS)

Los servicios se clasifican en tres capas principales: la Infraestructura como Servicio (IaaS) proporciona control total sobre redes y servidores virtuales, la Plataforma como Servicio (PaaS) ofrece entornos optimizados para el desarrollo sin la carga de administrar el sistema operativo; y el Software como Servicio (SaaS) entrega aplicaciones listas para su uso final.

Modelos de Implementación

Dependiendo del control de acceso, la nube se implementa de manera pública, compartiendo hardware físico entre múltiples usuarios de forma aislada; privada, asignando infraestructura exclusiva para una organización con requisitos estrictos de seguridad; o híbrida, comunicando ambos entornos para aprovechar sus respectivas ventajas.

Las "Tres Grandes" Nubes

El mercado está liderado por tres ecosistemas: Amazon Web Services (AWS), que sobresale por su madurez y un extenso catálogo de servicios globales; Google Cloud Platform (GCP), enfocada en soluciones analíticas de datos e inteligencia artificial; y Microsoft Azure, idónea para la integración de entornos corporativos y arquitecturas híbridas.

Gestión y Colaboración

La administración del código fuente se apoya en GitHub, ya que esta herramienta facilita el control de versiones y el trabajo colaborativo en equipos de desarrollo, registrando de forma transparente cada modificación y permitiendo integrar mejoras continuas a los repositorios de manera segura.

¿Qué aprendimos a hacer?

Las prácticas permitieron adquirir destreza en la navegación de consolas en la nube para aprovisionar cómputo y almacenamiento, asimismo, se crearon entornos colaborativos en GitHub, desarrollando la capacidad de evaluar e implementar la opción tecnológica que brinde mejor balance entre costo y necesidad.

Unidad 03

Consideraciones para el desarrollo

La transición desde arquitecturas monolíticas hacia sistemas basados en microservicios ha redefinido el ciclo de desarrollo de software y este enfoque modular divide la lógica de negocio en componentes independientes que facilitan considerablemente el mantenimiento, la escalabilidad y la entrega ágil.

¿Por qué aprender esto?

Comprender la descomposición de servicios y adoptar prácticas DevOps es vital para la agilidad operativa, con esta metodología nos facilita actualizaciones continuas y correcciones rápidas en producción, minimizando el tiempo de inactividad de las aplicaciones.

DevOps representa un cambio cultural que unifica el desarrollo y las operaciones, su implementación se apoya en la automatización de pruebas e integración, garantizando entregas de código rápidas, estables y seguras mediante tuberías de distribución continua.

¿Qué son los Microservicios?

Los microservicios son unidades de software independientes y desacopladas que se comunican mediante APIs y cada servicio se especializa en una tarea única, lo que permite modificar, actualizar o escalar de manera individual cada componente sin interrumpir la operación de los demás.

Filosofía DevOps y CI/CD

Las prácticas de integración y despliegue continuos (CI/CD) automatizan la compilación, pruebas y liberación del código fuente y al reducir la intervención manual en los despliegues, se incrementa la confiabilidad y consistencia del software, acelerando su llegada a producción.

Herramientas Clave

El ecosistema técnico se sustenta en Docker para aislar las aplicaciones en contenedores ligeros que funcionan de manera idéntica en cualquier servidor; Kubernetes para orquestar y balancear la carga de dichos contenedores a escala; y herramientas como Prometheus y Grafana para el monitoreo del rendimiento en tiempo real.

Unidad 04

Seguridad

En esta sección se analiza la protección de infraestructuras ante vectores de ataque modernos, ya que la ciberseguridad se aborda bajo una estrategia multidimensional que involucra el robustecimiento de servidores, la gestión de accesos y la concienciación de los usuarios.

¿Por qué aprender esto?

Dada la constante evolución de las amenazas cibernéticas, la seguridad debe integrarse desde el diseño inicial del sistema y gracias a conocer las técnicas de intrusión comunes permite estructurar contramedidas eficientes y construir entornos resilientes.

Amenazas y Vulnerabilidades

Se examinaron vulnerabilidades críticas como la inyección SQL, que permite a un atacante alterar consultas de bases de datos mediante entradas maliciosas; la escalada de privilegios, que aprovecha malas configuraciones del sistema para obtener accesos elevados; y el uso de técnicas de búsqueda avanzada (Google Dorks) para localizar recursos expuestos accidentalmente en internet.

Técnicas de Protección (Hardening)

El proceso de protección incluyó el hardening de servidores Apache mediante la desactivación de firmas del servidor y módulos innecesarios, además, se utilizó Wireshark para el análisis de tráfico y la detección de anomalías de red, estableciendo barreras robustas para mitigar la superficie de ataque y asegurar la resiliencia ante amenazas.

Gestión de Riesgos y Normativas

La seguridad administrativa se estructuró conforme a marcos internacionales como NIST y RMF para la identificación, evaluación y mitigación de riesgos, se definieron políticas de uso aceptable para el personal y directrices técnicas en software, como la gestión de certificados, parches del sistema, accesos remotos y respaldos periódicos.

Desafíos Prácticos (Wargames)

A través de laboratorios en OverTheWire (Bandit), se fortalecieron las habilidades en administración segura de Linux y navegación de sistemas de archivos, estos retos prácticos reforzaron el modelo de responsabilidad compartida, donde el proveedor garantiza la seguridad de la infraestructura y el usuario asegura los datos y las configuraciones.

Unidad 05

Diseño y Desarrollo de una aplicación informática en la nube

Durante esta unidad se llevó a cabo el diseño, despliegue y migración de aplicaciones locales hacia infraestructuras de nube pública, evaluando el uso de tecnologías que favorecen la alta disponibilidad y el rendimiento operativo.

¿Por qué aprender esto?

El dominio práctico del aprovisionamiento en la nube es clave para implementar servicios altamente disponibles, junto con la capacidad de estructurar desde redes aisladas hasta bases de datos gestionadas dota a los profesionales de competencias críticas para sustentar plataformas corporativas escalables.

Arquitecturas de Red (VPC)

Se diseñaron topologías de red privada virtual (VPC) utilizando subredes públicas y privadas para segmentar el tráfico, aislando las bases de datos de accesos externos directos, además la arquitectura se complementó con balanceadores para distribuir inteligentemente la carga de usuarios entre las instancias virtuales de servidores, maximizando la escalabilidad.

Docker y Contenerización

Se implementó la contenerización de servicios mediante Docker para garantizar la portabilidad del código fuente con todas sus dependencias, los contenedores comparten el kernel del host, lo que optimiza drásticamente el uso de memoria y procesamiento frente a las máquinas virtuales tradicionales, eliminando conflictos de versiones.

Entorno LAMP y Despliegue

Se desplegó la pila LAMP (Linux, Apache, MySQL, PHP) en instancias virtuales Linux, gestionando el acceso mediante llaves criptográficas SSH (.pem) para tareas de administración remota de forma segura, la carga, sincronización y transferencia de código fuente se realizó bajo los protocolos seguros de SCP.

Servicios Administrados (PaaS)

Se migró la base de datos local hacia Azure Database for MySQL, delegando las tareas de respaldo automático, actualización del motor y parches de seguridad en el proveedor cloud, las credenciales de conexión se aislaron de manera segura mediante variables de entorno, permitiendo enfocar los recursos en la optimización del código.
